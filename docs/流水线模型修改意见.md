## 结论

当前工程的核心结构还是单周期 CPU，见 `SingleCycleCPU.v`。  
它的关键问题是：

- PC、指令存储器、寄存器堆、ALU、数据存储器都在同一时钟周期里完成
- `ControlUnit` 在同一周期直接决定 `reg_we / mem_we / branch_taken`
- `RegisterFile` 在同一周期同时读写，且写回数据直接来自 `alu_result`
- 没有 `IF/ID`、`ID/EX`、`EX/MEM`、`MEM/WB` 这些流水线寄存器
- 也没有 Forwarding / Stall / Flush

所以要改成“5 级流水线硬布线 CPU”，最核心的改动不是加几个模块，而是把“单周期数据通路”拆成“流水线阶段 + 流水线寄存器 + 冒险处理”。

---

## 一、先明确你要保留的模块

这份现有代码已经很接近“经典 RISC-V 子集 CPU”了，建议保留以下结构：

- `PC.v`  
  继续负责 PC 更新，改成“IF 阶段更新 PC”
- `InstructionMemory.v`  
  继续作为 IF 阶段取指
- `RegisterFile.v`  
  保留，但改成只在 WB 阶段写回
- `ALU.v`  
  继续作为 EX 阶段计算单元
- `DataMemory.v`  
  继续作为 MEM 阶段访存
- `ImmediateGenerator.v`  
  继续保持，输出在 ID 阶段生成
- `ControlUnit.v`  
  需要重构：从“单周期控制器”改成“ID 阶段解码器”

---

## 二、最核心的改动：把单周期顶层拆成 5 级流水线

### 1. 新增 4 组流水线寄存器

你需要在顶层新加这些寄存器，逻辑如下：

- IF/ID
  - `pc_plus_4_if`
  - `instr_if`
- ID/EX
  - `pc_plus_4_id`
  - `rs1_data`, `rs2_data`
  - `imm_ext`
  - `rs1_addr`, `rs2_addr`, `rd_addr`
  - `alu_ctrl`
  - `alu_src_sel`
  - `alu_src1_sel`
  - `mem_we`, `mem_to_reg`, `reg_we`
  - `branch_target`, `branch_type`
- EX/MEM
  - `alu_result`
  - `rdata2`（存储数据）
  - `rd_addr`
  - `mem_we`, `mem_to_reg`, `reg_we`
  - `branch_taken`
  - `branch_target`
- MEM/WB
  - `alu_result`
  - `mem_rdata`
  - `rd_addr`
  - `reg_we`
  - `mem_to_reg`

最重要的是：每个阶段只负责自己的事情，不能再让上一阶段的信号直接驱动后面的组合逻辑。

---

### 2. 把 PC 更新逻辑从顶层“直接做”改成流水线 IF 阶段

现在的写法是：

- 在 `SingleCycleCPU.v` 里直接算：
  - `pc_plus_4`
  - `pc_branch`
  - `next_pc = branch_taken ? pc_branch : pc_plus_4`

这在单周期下没问题，但流水线里必须改为：

- IF 阶段：
  - `pc <= pc + 4`，或者在有分支时送入 `branch_target`
- 分支判断放在 EX 阶段，分支结果确定后：
  - 需要清空 IF/ID 和 ID/EX 中错误的指令
  - 也就是 branch flush

也就是说，`branch_taken` 不再是“解码器直接输出”，而应该变成：
- 在 EX 阶段由 ALU + 判断逻辑产生
- 然后驱动 flush 控制

---

## 三、ControlUnit 需要改成“解码 stage”，不是“总控 stage”

你现在的 `ControlUnit.v` 里有：

- `branch_taken`
- `reg_we`
- `mem_we`
- `alu_ctrl`
- `alu_src_sel`
- `alu_src1_sel`

这些在单周期 CPU 下都可以直接用。

但在流水线中，必须分成两类：

### A. ID 阶段解码产生的信号
这些应该传入 ID/EX：
- `alu_ctrl`
- `alu_src_sel`
- `alu_src1_sel`
- `mem_we`
- `mem_to_reg`
- `reg_we`
- `imm_type`
- `branch_type`
- `is_jal`

### B. EX 阶段才确定的信号
这些不应该在 ID 阶段直接生成：
- `branch_taken`
- 真实的分支是否跳转
- 目标地址是否有效

也就是说，控制器不能再“直接给最终的分支结果”；它只负责“告诉后面这条指令是什么类型”，真正的分支决策在 EX。

---

## 四、数据冒险：Forwarding + Stall 必须加

这是流水线 CPU 里最关键的地方。你文档里提到的最简方案是对的：

### 1. Forwarding
在 EX 阶段，ALU 的源操作数来自：

- `ID/EX.rs1_data`
- `ID/EX.rs2_data`
- 但如果上一条指令刚写回，应该优先使用：
  - EX/MEM.alu_result
  - MEM/WB.writeback_data

所以要加 2 条前递：

- `EX/MEM -> EX`
- `MEM/WB -> EX`

### 2. Load-use hazard
例如：

```
lw x1, 0(x2)
add x3, x1, x4
```

这里 `x1` 读到的值在 MEM 阶段才得到，EX 阶段还没完成。  
所以要加：

- `Hazard Detection Unit`

它的核心判断是：

- 如果 `ID/EX.mem_read == 1`
- 且 `ID/EX.rt` 等于 `IF/ID.rs1` 或 `IF/ID.rs2`

则：
- 暂停 IF/ID 和 ID/EX
- 让流水线停一个周期，避免取到错误数据

这也是最经典且最容易写的方案。

---

## 五、控制冒险：分支 flush 必须加

你的代码现在的分支逻辑非常简单：

- `beq` / `blt` / `bge` / `jal` 都在一个周期里决定

这个在流水线中会造成错误，因为分支目标并不在同一时钟周期就能让前面的指令消失。

### 应该这样做：

- IF 阶段先取指
- ID 阶段解码
- EX 阶段计算分支条件
- 如果分支成立：
  - 清空 IF/ID
  - 清空 ID/EX
- 重新从新地址取指

这就是“Branch Flush”。

你无需设计复杂分支预测器，文档里建议的做法就是最合适的。

---

## 六、寄存器堆要改成“写在 WB 阶段”

现在 `RegisterFile.v` 里：

- 写操作同步在 `clk` 上升沿
- 读操作是组合逻辑
- 但你当前写回是使用同一周期的 `alu_result`

这会导致流水线存在写回冲突。

你需要改成：

- `rs1`, `rs2` 在 ID 阶段读出
- `waddr`, `wdata`, `reg_we` 在 WB 阶段写入
- 读写地址来自不同阶段，不再在一个周期同时“取指+写回”发生

这点非常重要，否则流水线会有严重的寄存器冲突。

---

## 七、ALU 和 ImmediateGenerator 可以大体保留，但输入要改到阶段中

### ALU
`ALU.v` 目前适合保留。  
它本身是组合逻辑，不需要大改，反而更适合放在 EX 阶段。

只是它的输入必须不再直接来自顶层：
- 改成 `id_ex_rs1`, `id_ex_rs2` 或 forwarding 后的值
- 不再直接接 `RegisterFile` 的输出

### ImmediateGenerator
`ImmediateGenerator.v` 也可以保留，  
但它的输入应该来自 ID 阶段的当前指令，并且输出应在 ID/EX 寄存器中保存。

## 八、你应该把整个顶层拆成类似这种结构

建议你把 `SingleCycleCPU.v` 改成类似下面这个样子：

1. IF
   - PC
   - InstructionMemory
   - `if_id_pc`
   - `if_id_instr`

2. ID
   - `rs1 = instr[19:15]`
   - `rs2 = instr[24:20]`

   - `ControlUnit`
   - `ImmediateGenerator`

3. EX

   - ALU

4. MEM

5. WB
   - `mem_to_reg` 选择
   - `regfile.write` 发生在这里

## 三、先给你一版 IF 阶段代码

下面这份代码是“最小可行版”。  
它的作用是：

- 维护 PC
- 取指令
- 生成 `if_id_pc` 和 `if_id_instr`
- 处理 `flush` 和 `stall`

你可以先把它放进一个新文件，比如 `IF_Stage.v`，然后在顶层 CPU 中替代原来的 `PC + InstructionMemory` 直接连接方式。

```verilog
`timescale 1ns / 1ps

module IF_Stage (
    input  wire        clk,
    input  wire        rst,
    input  wire        stall,        // 暂停信号
    input  wire        flush,       // 清空当前取到的错误指令
    input  wire [31:0] branch_target, // 分支跳转地址
    input  wire        branch_taken, // 是否发生跳转
    output reg  [31:0] if_id_pc,    // 传给 ID 阶段的 pc
    output reg  [31:0] if_id_instr, // 传给 ID 阶段的 instr
    output wire [31:0] curr_pc      // 当前 PC，供调试/外部观察
);

    reg  [31:0] pc;
    wire [31:0] pc_plus_4;
    wire [31:0] next_pc;
    wire [31:0] instr;

    // PC + 4
    assign pc_plus_4 = pc + 32'd4;

    // 分支选择
    assign next_pc = branch_taken ? branch_target : pc_plus_4;

    // 指令存储器
    InstructionMemory im_inst (
        .addr(pc),
        .instr(instr)
    );

    // 当前 PC 输出
    assign curr_pc = pc;

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            pc         <= 32'h00400000;   // RISC-V 程序入口
            if_id_pc   <= 32'b0;
            if_id_instr <= 32'b0;
        end
        else if (flush) begin
            // 分支/跳转发生，清空 IF/ID 中的错误指令
            pc         <= branch_target;
            if_id_pc   <= 32'b0;
            if_id_instr <= 32'b0;
        end
        else if (stall) begin
            // 暂停，不取新指令，不更新流水线寄存器
            pc <= pc;
        end
        else begin
            // 正常推进
            pc <= next_pc;
            if_id_pc <= pc_plus_4;   // 也可按你们习惯保存 pc 或 pc_plus_4
            if_id_instr <= instr;
        end
    end

endmodule
```

## 四、这段代码对应你现有工程的改法

你现在的 `SingleCycleCPU.v` 是：

- 直接用 `curr_pc`
- 直接做 `next_pc = branch_taken ? pc_branch : pc_plus_4`
- 直接拿 `instruction`
- 直接连 `RegisterFile` 和 `ALU`

这在单周期 CPU 里没问题，但在流水线里就不能这么做了。

你要改成的核心思路是：

- `PC` 只在 IF 阶段维护
- `InstructionMemory` 只在 IF 阶段读
- 取出来的 `instr` 先送到 `IF/ID` 寄存器
- ID 阶段用 `instr` 解码和读取寄存器
- 不再让 ID/EX 直接使用顶层信号

也就是你要把原来的顶层组合逻辑拆成：

```verilog

ID_Stage        -> ID_EX
EX_Stage        -> EX_MEM
MEM_Stage       -> MEM_WB
```
