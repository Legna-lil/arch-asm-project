如果你的目标是“尽量简单、工作量可控、容易仿真通过、报告也好写”，我建议选下面这套组合：

### 推荐方案：5级流水线 MIPS/RISC-V 子集 CPU + 硬布线控制器 + 溢出判断 + UART 接口

整体可以定成：

> **基于硬布线控制器的五级流水线 RISC-V/MIPS CPU 设计与实现，并集成 UART 串口控制器。**

其中我更推荐 **RISC-V RV32I 子集**，因为指令格式规整、资料多、译码简单；如果你们之前大三做的是 MIPS 单周期 CPU，那么继续做 MIPS 也完全可以，而且复用以前代码会更省事。

------

## 一、CPU部分怎么选最简单

采用经典的 **5级流水线**：

**IF → ID → EX → MEM → WB**

也就是：

- IF：取指
- ID：译码、读寄存器
- EX：ALU运算
- MEM：访存
- WB：写回寄存器

这是最经典、资料最多、最容易解释的流水线结构。

控制器选择：

> **硬布线控制器**

不要做微程序控制器。因为你们本身还要处理流水线，如果再加微程序控制器，设计复杂度会明显上升。

------

## 二、指令集建议控制在16～20条

不要贪多，刚刚超过16条即可。

如果采用 RISC-V，可以选这18条左右：

### 运算类

- ADD
- SUB
- AND
- OR
- XOR
- SLT
- SLL
- SRL

### 立即数类

- ADDI
- ANDI
- ORI

### 数据传送类

- LW
- SW

### 控制类

- BEQ
- BNE
- JAL

再补两条：

- LUI
- SRA

一共18条。

这样已经完全满足：

> 运算类 + 传送类 + 控制类

三类指令都有，而且实现难度不高。

------

# 三、附加功能建议只选“溢出判断”

附加功能里面最推荐：

> **支持溢出判断**

因为这个几乎是白送的功能。

比如有符号加法：

```
A > 0，B > 0，但是结果 < 0 → 溢出
A < 0，B < 0，但是结果 > 0 → 溢出
```

Verilog里面增加几个逻辑判断即可。

相比之下：

- Cache：明显复杂
- 分支预测：要增加预测器、预测失败恢复
- 中断：要保存PC、增加异常入口
- 浮点：很复杂
- 超标量：不建议碰
- 多核：更不建议

所以建议直接：

> **五级流水线 + 硬布线 + 溢出检测**

足够完成要求，也不会给自己增加太多麻烦。

------

# 四、流水线相关问题怎么解决

这个是报告重点，但实际上可以采用最经典方案。

## 1. 数据相关

主要就是 RAW：

```
add x1, x2, x3
sub x4, x1, x5
```

第二条马上需要第一条的结果。

推荐：

> **数据前递 Forwarding + 必要时 Stall**

增加两个前递：

```
EX/MEM → EX
MEM/WB → EX
```

这样绝大多数数据冒险不用暂停。

但是 `LW` 后立即使用：

```
lw  x1, 0(x2)
add x3, x1, x4
```

仍然需要：

> 暂停1个周期。

所以增加一个简单的：

> Hazard Detection Unit

即可。

这也是教科书最标准的设计。

------

## 2. 控制相关

例如：

```
beq x1,x2,label
```

最简单的做法不是分支预测，而是：

> **分支结果在 EX 阶段确定，如果跳转，则 Flush 前面的错误指令。**

也就是清空 IF/ID、ID/EX。

虽然性能一般，但是实现非常简单，而且报告很好解释。

------

## 3. 结构相关

最简单的方法是：

> **指令存储器和数据存储器分离。**

即：

```
Instruction Memory
Data Memory
```

这样 IF 阶段取指和 MEM 阶段访存不会冲突。

也就是类似 Harvard 结构。

于是结构相关基本就直接解决了。

------

# 五、整个CPU结构可以做成这样

```
                 ┌─────────┐
PC ─────────────>│ InstrMem│
                 └────┬────┘
                      │
                     IF
                      │
                  IF/ID寄存器
                      │
                      ▼
              ┌─────────────┐
              │ Decoder     │
              │ RegisterFile│
              └──────┬──────┘
                     ID
                      │
                  ID/EX寄存器
                      │
                      ▼
                ┌─────────┐
         ──────>│   ALU   │
        Forward └────┬────┘
                     EX
                      │
                 EX/MEM寄存器
                      │
                      ▼
                  Data RAM
                     MEM
                      │
                 MEM/WB寄存器
                      │
                      ▼
                Register File
                     WB
```

旁边再加两个小模块：

```
Forwarding Unit
Hazard Detection Unit
```

基本就是完整CPU了。

# 六、汇编与接口课程建议选UART

接口里面建议选：

> **UART**

不要选 VGA/LCD。

UART最大的优势就是逻辑简单：

```
CPU
 │
 ├── RAM
 │
 └── UART
      │
      ├── TX
      └── RX
```

UART控制器主要就：

- 波特率发生器
- UART发送模块
- UART接收模块
- 几个控制/状态寄存器

甚至如果想进一步降低工作量，可以第一版：

> **只实现 UART TX**

如果课程明确要求完整接口控制器，再补 RX。

# 七、CPU和UART怎么连接

推荐采用：

> **Memory-Mapped I/O，存储器映射I/O**

例如定义：

```
0x00000000 ~ 0x00000FFF    RAM

0x10000000                 UART_DATA
0x10000004                 UART_STATUS
```

那么CPU执行：

```
sw x1, 0(x2)
```

如果：

```
x2 = 0x10000000
```

就不是写RAM，而是把数据发给UART。

硬件判断：

```
if(address == 32'h10000000)
    uart_data <= write_data;
else
    ram[address] <= write_data;
```

这样CPU完全不需要增加特殊UART指令。

这是比较标准且简单的设计。

# 九、性能测试怎么做最省事

课程要求：

> 流水线 CPU vs 大三单周期 CPU

建议直接选择：

> **CPI + CPU执行时间**

两个指标。

假设测试程序有100条动态指令。

单周期：

```
Cycles = 100
CPI = 1
```

但是单周期时钟周期很长，比如：

```
Tsingle = 20 ns
```

CPU时间：

```
100 × 20ns = 2000ns
```

流水线可能因为冒险：

```
Cycles = 100 + 4 + stall + flush
       = 115
```

所以：

```
CPI = 115 / 100 = 1.15
```

但是流水线时钟周期可能只有：

```
Tpipeline = 6ns
```

因此：

```
CPU时间 = 115 × 6ns
        = 690ns
```

于是加速比：

```
Speedup = 2000 / 690
        ≈ 2.9
```

这就很好解释一个重要结论：

> 流水线CPU的CPI可能略高于1，但由于时钟周期显著缩短，因此总体CPU执行时间明显下降。

当然，你们最终报告必须用自己实际 Vivado 仿真的真实数据，不能直接用上面的示例数值。

# 十一、最终推荐你们的完整选题

我觉得可以直接叫：

> **基于RV32I指令集的五级流水线CPU及UART接口计算机系统设计与实现**

配置为：

| 项目         | 选择                |
| ------------ | ------------------- |
| 指令集       | RISC-V RV32I 子集   |
| 指令数量     | 18条左右            |
| 流水线       | 经典5级流水         |
| 控制器       | 硬布线              |

| 附加功能     | 溢出检测            |
| 外设         | UART                |
| CPU-外设连接 | Memory-Mapped I/O   |

这个方案的一个很大优势是：**所有模块基本都有成熟的教科书结构，不需要自己发明复杂机制。**

尤其不建议一开始就选 Cache、分支预测、VGA、LCD、浮点、超标量这些，因为你们这个课设真正容易出问题的地方通常不是“功能不高级”，而是**五级流水线数据通路、流水线寄存器、Forwarding、Stall、Flush之间的控制容易出bug**。先把基础流水线跑通，再考虑额外加分项会更稳。

如果你们大三已经做过 **MIPS单周期CPU**，那我甚至建议直接把上面的 RISC-V 换成 **MIPS 16～20条指令子集**，在原有单周期CPU上改五级流水线，这通常会是整个课设**工作量最小的路线**。
